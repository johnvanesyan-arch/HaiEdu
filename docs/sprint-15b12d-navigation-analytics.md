# 15B.12D — navigation, role dashboards and analytics

Student navigation uses live, server-authorized enrollment/release/unit UUIDs. Same-named subjects, chapters and classes stay distinct across schools and years. The catalog and dashboard RPCs are read-only, share the learning engine's context locks and final clock checks, and create no sessions, policies or evidence.

The selected workspace derives question counts, hint availability, pass minima, readiness and lifecycle limits from governed policies. Any completed chapter diagnostic unlocks that chapter's practice; the initial baseline remains visible separately from mastery. Active assessments withhold running correctness and readiness. History retains original release, blueprint, policy binding, model, runtime build and lifecycle policy IDs. The registered legacy extension preserves existing criteria and its topic/task pages; no prospective policy is synthesized for it. Unsupported/unconfigured capabilities remain unavailable.

The configured player uses the actual served question count and server-owned option presentation, grading and authored help. It guards duplicate submissions and late responses after chapter/account changes. Resumed sessions retain their original binding. Subject-specific stimulus renderers remain scoped compatibility extensions; the new workspace supports explicit text/image media and selected-response capabilities. A future content release must declare supported delivery capabilities and follow the platform-wide textbook illustration policy.

Teacher analytics load only the selected release/unit's frozen question versions and exact original class/enrollment sessions. The explicit linear-beta adapter reads each session's original immutable model; missing provenance does not get default weights or thresholds. Estimates describe class/contract evidence, not the learner-wide readiness state. Different contracts stay separate. Completed sessions retain provenance in the drawer. Closed original years and ended original assignments are read-only to the same currently authorized teacher; current membership, account and subject grants still apply. A replacement teacher cannot inherit another assignment through a mutable class owner field.

School and Master Admin analytics share the school-scoped API. Filters include year, programme, class, release and chapter. Enrollment/student pairs and full institutional context must match. Historical year denominators retain ended enrollment cohorts, excluding revoked/future records. Participation and completion counts can aggregate; performance results remain grouped by original contracts. No comparability mapping or cross-subject grade is invented. Role views clear stale data during context changes and sign-out.

D does not activate a second curriculum release, change learning criteria or rewrite historical records. Full authenticated governed multi-context learner acceptance remains in 15B.12E and requires a second authorized release. Release verification and deployment evidence will be appended after all required PR/main jobs pass.
